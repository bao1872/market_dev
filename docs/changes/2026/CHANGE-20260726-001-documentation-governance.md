## 1. 摘要

将原本混合保存需求、当前实现、开发流程和历史记录的文档体系，拆分为 `AGENTS.md`、`rules/`、`docs/prd/`、`docs/maps/`、`docs/changes/` 和 `docs/runbooks/` 各自负责的结构。

## 2. 背景与问题

原文档体系存在以下问题：

- `AGENTS.md` 包含过多项目当前状态和可变实现细节；
- `docs/current/` 同时混合目标要求与当前实现；
- 需求和代码入口缺少稳定对应关系；
- 重要变化和普通开发过程边界不清；
- AI/IDE 容易依据旧文档推测当前状态；
- 文档数量增加，但下一次任务仍需要重新理解项目。

## 3. 变化前

已知原结构包含：

- 较长的 `AGENTS.md`；
- `docs/current/`；
- `maps/`；
- `changes/`；
- `runbooks/`；
- `decisions/` 或 ADR；
- 多项治理检查。

具体仓库状态必须由后续审计核验。

## 4. 变化内容

### AGENTS

收敛为长期稳定的 AI/IDE 工作协议和文档路由。

### Rules

只约束代码风格、逻辑组织和实现方式，例如：

- SSOT；
- 状态所有权；
- 分层边界；
- 错误处理；
- 技术栈约定；
- 测试代码规范；
- 禁止的代码模式。

### PRD

定义“系统应该怎样工作”，并使用稳定条款编号。

### Maps

与 PRD 按领域和编号对齐，记录：

- 当前实现入口；
- 当前实现状态；
- 验证证据；
- 与 PRD 的偏差。

### Changes

只记录重要行为、契约、架构、运行和数据变化。

### Runbooks

只记录可重复执行的操作步骤。

## 5. 变化后

目标结构：

```text
AGENTS.md
rules/
docs/
├── prd/
├── maps/
├── changes/
└── runbooks/
```

当前本 Change 包含 PRD、Maps 和 Changes 的最终设计文件；实际仓库迁移和旧文件清理尚待完成并核验。

## 6. 影响范围

### 开发工作流

新需求先修改 PRD，开发验证后更新 Maps，重要变化创建 Change。

### 文档维护

不再由一份文档同时承担需求、实现和历史。

### AI/IDE

读取路径按任务最小化，不能将 PRD 目标推测为当前实现。

### Git 历史

普通小 Bug 和普通修改继续由 Git 历史承担。

## 7. 迁移与兼容

迁移时需要：

1. 拆分 `docs/current/` 中的目标要求和当前事实；
2. 将目标要求迁移到 PRD；
3. 基于真实代码重建 Maps；
4. 将重要历史迁移到 Changes；
5. 将具体操作迁移到 Runbooks；
6. 删除旧事实源，避免双轨维护。

不得直接把 `current/` 整体重命名为 `prd/`。
