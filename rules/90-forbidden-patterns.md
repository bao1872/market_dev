# 禁止的代码模式

以下模式默认禁止。确有必要时，必须有清楚理由并经过明确确认。

## 1. 重复权威逻辑

禁止：

- 同一业务判断复制到多个模块；
- 前端重新计算后端权威状态；
- Worker 复制领域算法；
- 新旧两套实现同时承担正式职责；
- 同一字段在不同层拥有不同语义。

## 2. 隐藏失败

禁止：

- 裸 `except`；
- 捕获异常后 `pass`；
- 捕获异常后无记录返回空值；
- 用默认值掩盖数据缺失；
- 把业务失败返回为成功；
- 部分失败时标记整体成功；
- 静默 fallback。

## 3. 隐式状态和环境判断

禁止：

- 依赖模块导入顺序；
- 依赖全局可变单例；
- 根据主机名、目录或 IDE 类型猜测环境；
- 在业务代码中散落读取环境变量；
- 在多个位置独立维护同一页面或任务状态。

## 4. 写死配置和凭据

禁止在代码中写死：

- 数据库地址；
- Redis 地址或逻辑库；
- 密码；
- Token；
- 私钥；
- 环境专用路径；
- 未命名业务阈值。

## 5. 越层实现

禁止：

- API 路由直接实现复杂业务算法；
- Repository 承担业务判断或页面展示；
- Worker 直接复制业务计算；
- 展示组件直接修改共享领域状态；
- 核心计算直接依赖 Web、Redis 或 UI 对象。

## 6. 无边界数据库操作

禁止：

- 无过滤条件 `UPDATE`；
- 无过滤条件 `DELETE`；
- 查询范围依赖危险默认值；
- 在循环中逐条查询造成明显 N+1；
- 在普通业务函数中创建独立 Engine；
- 修改已执行的历史 Migration；
- 在 Migration 中执行不可控长时间业务任务。

## 7. 类型逃逸

禁止：

- 无理由使用 `Any` 或 TypeScript `any`；
- 通过大范围类型忽略解决正常类型问题；
- 用强制类型断言掩盖接口不一致；
- 用无约束字典代替稳定公共契约；
- 混淆零值、空值、未加载和失败。

## 8. 过度抽象

禁止：

- 为单一场景建立通用框架；
- 为假设未来需求增加扩展层；
- 用继承树复用少量代码；
- 通过大量布尔参数控制完全不同逻辑；
- 把简单流程拆成难以追踪的多层间接调用。

## 9. 死代码和长期临时补丁

禁止：

- 长期保留注释掉的大段旧代码；
- 保留无调用旧入口“以防万一”；
- 没有移除条件的临时分支；
- 永久存在且无人负责的 TODO；
- 通过复制文件保留历史版本。

## 10. 不稳定测试

禁止：

- 测试依赖执行顺序；
- 测试依赖真实当前时间；
- 用长时间 sleep 规避竞态；
- Mock 掉被测试的核心逻辑；
- 通过放宽断言迎合错误实现；
- 依赖不可控外部服务却不明确标记。

## 11. 无关大范围修改

禁止在局部任务中：

- 全项目重命名；
- 更换框架；
- 更换格式化工具；
- 重写无关模块；
- 大范围格式化；
- 添加新的治理或文档体系。

## 12. 虚假完成状态

禁止在没有证据时声称：

- Bug 已修复；
- 测试已通过；
- 数据已修复；
- 任务已完成；
- 部署已生效；
- 远程运行正常。

未运行、部分验证、阻塞和失败必须如实说明。
