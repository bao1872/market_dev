## 2. 修改前理解

- 当前产品行为：盘中监控截图由 CaptureStockPage → MobileIndicatorStage → StrategyChart → Playwright 截取 `data-testid="stock-detail-capture"` 生成；三类 indicator_view（node_cluster/bollinger/smc）共用同一 MobileIndicatorStage 舞台，底部仅有风险提示文案，无二维码入口。
- 当前前端流程：CaptureStockPage 使用 captureClient 调用 Snapshot API，渲染 MobileIndicatorStage（1440×2560），Playwright 等待 `data-render-ready="true"` 后截图。
- 当前门户：`/portal/pages/data.html` 为旧版指标原理页，内容简单，无动画交互。
- 已阅读文件：CaptureStockPage.tsx、MobileIndicatorStage.tsx、StrategyChart.tsx、global.scss、stock_capture_service.py、data.html、site.css、site.js、portal-static.test.ts、capture-stock-page.test.ts。

## 3. 修改目标

- 当前问题：盘中监控截图无指标原理解读入口；指标原理页内容陈旧，缺乏动画演示。
- 修改后行为：
  1. 指标原理页（`/portal/pages/data.html`）替换为新版，包含筹码共识 6 步 + 价格结构 5 步动画，支持上一步/下一步/步骤选择/可选自动播放，默认不自动播放，不依赖外部 CDN，移动端正常显示。
  2. 三类 indicator_view 截图（node_cluster/bollinger/smc）共用 MobileIndicatorStage 底部二维码页脚，QR 指向 `/portal/pages/data.html`，主文案"扫码了解原理和解读方法"。
  3. 二维码使用项目本地静态资源 `/portal/assets/images/indicator-principles-qr.png`，Capture 时不请求第三方服务。
- 验收标准：三类截图均 1440×2560、二维码区域可见、图表无覆盖、contract tests 通过、tsc/eslint/build 通过。
- 明确不修改：后端指标算法、Node Cluster/Bollinger/SMC 计算、Capture Snapshot API 契约、indicator_view 参数、render_frame matched 校验、computeTypeSpecificReady、data-render-ready 逻辑、Screenshot cache key、飞书上传与发送逻辑、数据库模型、migration、Worker 调度、盘中监控触发条件、StrategyChart 图层计算。
