# 跨系统统一要求 PRD

状态：已确认  
最后确认日期：2026-07-26  
对应 Map：`../maps/90-system-wide-implementation.md`  
需求所有权：跨模块统一时间、状态、标识、来源和非功能要求

## 1. 时间

### SW-01 统一时区

业务日期和交易时间使用 `Asia/Shanghai`。

### SW-02 时间语义明确

必须区分：

- 行情发生时间；
- 数据获取时间；
- 计算时间；
- 发布时间；
- 用户界面显示时间。

## 2. 标识

### SW-10 稳定标识

跨模块至少统一：

- symbol；
- trade_date；
- run_id；
- published_run_id；
- user_id；
- event_id 或等价事件标识。

### SW-11 标识不可由展示名称替代

业务关联不得依赖股票名称、用户名或可变文案。

## 3. 状态

### SW-20 统一状态语义

跨模块明确区分：

- 未加载；
- 无数据；
- 不可用；
- 失败；
- 部分完成；
- 已完成；
- 已发布；
- 过期或 stale。

### SW-21 失败不伪装成功

任何模块不得通过默认值、空对象或成功状态掩盖失败。

## 4. 来源和版本

### SW-30 来源可追踪

正式结果应能够追踪必要的数据来源和 fallback 状态。

### SW-31 运行版本可追踪

盘后正式结果应能够关联必要的 run 和代码或算法版本信息。

## 5. 权威事实源

### SW-40 单一正式结果

前端、API、Worker 和调试工具不得各自维护独立的正式结果语义。

### SW-41 调试与正式结果分离

局部调试、实验、未校验结果和正式发布结果必须可区分。

## 6. 可观察性

### SW-50 关键失败可见

关键数据、任务、发布和权限失败必须有结构化状态或可定位证据，不能只存在于临时日志。

### SW-51 不虚构完成

没有实际验证证据时，不得标记任务、部署、数据修复或正式运行成功。

## 7. 验收标准

- 同一状态和标识在前端、API、数据库和任务系统中语义一致。
- Map 能指向各统一语义的权威代码、Schema 或配置。
- 任何已知不一致在 Map 中显式列出。
