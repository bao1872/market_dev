# CHANGE-20260725-003：左栏来源列表可见性修复（missing_origin invalid + reason 显示）

## 变更编号
CHANGE-20260725-003

> 注：任务描述原指定编号 CHANGE-20260725-001，但该编号已被 freshness_state 日级周期修正变更占用，故顺延为 CHANGE-20260725-003。

## 任务名称
左栏来源列表可见性修复（missing_origin invalid + reason 显示）

## 需求出处
用户报告：个股详情页左栏来源列表在某些入口场景下消失（缺 originScope 时被默认 direct，导致静默回退单列布局，左栏不可见）。

## 修改前行为
1. `resolveDetailSourceContextV2` 在缺 `originScope` 且无有效 `/market` `returnTo` 时默认 `origin=direct`
2. 默认 direct 触发单列布局（无左栏），用户看到来源列表静默消失
3. invalid 占位不显示具体 reason，用户无法判断为何左栏缺失
4. V1 `resolveDetailSourceContext` / `resolveStockDetailOrigin` 仍可作为来源上下文解析入口（与 V2 并存，存在双源风险）

## 修改后行为
1. `resolveDetailSourceContextV2` 缺 `originScope` 且无有效 `/market` `returnTo` 时**不再默认 direct**，改为 `missing_origin` invalid 占位：
   - `origin=watchlist`（占位）
   - `contextInvalid=true`
   - `invalidReason="missing_origin"`
2. 左栏渲染 invalid 占位而非单列布局（合同 5：只有显式 `originScope=direct` 才使用单列布局）
3. invalid 占位显示具体 reason：
   - `StockDetailPage` 左栏 invalid 分支渲染 `data-invalid-reason` 属性
   - `INVALID_REASON_LABELS`（`frontend/src/pages/StockDetailPage.tsx`）提供中文文案（`missing_origin` → "缺少来源上下文"等）
   - 禁止空占位
4. V1 `resolveDetailSourceContext`（`detailSourceContext.ts`）/ `resolveStockDetailOrigin`（`stockDetailNavigation.ts`）标记 `@deprecated`，**V2 `resolveDetailSourceContextV2` 为唯一真源**（禁止新增 V1 调用）
5. `market`/`watchlist` 入口必须携带完整 `sourceRunId` + `canonicalQuery`（`buildStockDetailUrl` 强制透传），缺任一字段视为 missing_origin invalid

## 影响范围
- frontend 详情页左栏来源列表

## 根因
`resolveDetailSourceContextV2` 缺 `originScope` 时默认 `direct`，导致左栏静默消失（单列布局无左栏）。

## 修复
- 改为 `missing_origin` invalid 占位 + 显示 reason
- V1 标记 `@deprecated`，V2 为唯一真源
- invalid 占位显示 `data-invalid-reason` 属性 + `INVALID_REASON_LABELS` 中文文案
