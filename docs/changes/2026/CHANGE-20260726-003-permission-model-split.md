## 1. 摘要

将用户能力拆分为自选管理、行情管理和复盘管理三个独立权限；自选管理包含盘中监控和可配置股票数量，行情管理不自动包含自选和盘中，复盘管理为独立未来能力。

## 2. 背景与问题

旧权限模型可能存在：

- 自选、行情和盘中能力边界不清；
- 自选股票数量使用固定范围；
- 前端可见性与后端授权不一致；
- 仅拥有自选权限的用户可以进入不应访问的个股详情；
- 行情权限错误包含自选或盘中；
- “复盘管理”名称存在，但功能未定义。

实际旧实现必须由 Map 审计确认。

## 3. 变化前

待从权限表、邀请码、API 依赖、前端路由和页面可见性核验。

## 4. 变化内容

### 自选管理

- 包含自选列表；
- 包含盘中监控；
- 管理员自由设置股票数量；
- 可以查看行情标签下列表视图；
- 不因自选权限自动获得个股详情明细。

### 行情管理

- 可以查看行情能力和个股详情；
- 不自动拥有自选列表；
- 不自动拥有盘中监控。

### 复盘管理

- 独立授权；
- 具体产品能力尚待定义；
- 不得提前推断并建设复杂复盘功能。

### 邀请码

管理员创建时选择：

- 权限组合；
- 自选数量；
- 按自然月表达的有效期；
- 必要备注。

## 5. 变化后

目标权限矩阵以 `prd/60-permissions-admin.md` 为准。

当前实现矩阵必须在 `maps/60-permissions-admin.md` 中基于真实代码逐项填写。

## 6. 影响范围

### 用户行为

不同权限用户可见页面和可执行操作发生变化。

### 后端

需要在 API 和业务层强制检查权限与自选数量。

### 前端

页面隐藏、路由保护和用户提示需与后端一致。

### 数据

权限字段、邀请码和有效期可能需要迁移。

### 盘中监控

盘中对象和入口归属自选管理。

## 7. 迁移与兼容

需核验：

- 旧权限字段；
- 已有用户权限；
- 旧邀请码；
- 自选数量；
- 有效期；
- 前端缓存；
- 路由保护。

如果旧字段仍被远程稳定代码使用，需要兼容过渡后再清理。

权限迁移回滚必须保护已有用户能力，不能简单清空权限表。

需要：

- 保存旧到新权限映射；
- 明确回滚后的默认能力；
- 验证受限 API 和用户页面；
- 防止权限扩大。
