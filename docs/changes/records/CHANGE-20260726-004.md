# CHANGE-20260726-004：Reports 报告体系收口修正

## 变更编号

CHANGE-20260726-004

## 任务名称

Reports 报告体系收口修正

## 需求出处

用户指令：执行 Reports 报告体系收口修正。本轮只修 reports 体系自身的问题，不开展 Phase 3、maps 迁移或自动部署。修正 SHA 语义为三字段、统一检查项数量为 15 个检查组、修复 secret 检测、强化 SHA 一致性检查、为 reports CI job 增加 fetch-depth: 0。

## 修改前行为

1. 报告使用单一 `End SHA` 字段，语义模糊（无法区分 implementation commit 与 metadata commit）；
2. `reports/LATEST.md` End SHA 写 012681，不等于远程 dev 当前 HEAD（d99a5b）；
3. 部分报告文字写成"18 项检查"，实际为 15 个检查组；
4. `secret=` 检测正则 `\S+` 会匹配中文说明文字，存在误报风险；
5. SHA 一致性检查仅校验 End SHA 非空，不校验格式/commit 有效性/祖先关系/LATEST 一致性；
6. reports job 使用浅克隆，无法执行 SHA 祖先检查；
7. 无 check_reports.py 自测。

## 修改后行为

1. 报告使用三字段：Base SHA / Implementation SHA / Report Published Through SHA，语义清晰；
   - Base SHA：任务开始时基于的 origin/dev commit；
   - Implementation SHA：完成任务主体内容的 commit；
   - Report Published Through SHA：报告内容和元数据已覆盖到的已知 commit；
2. 报告文件不能可靠记录包含其自身的最终 commit SHA；禁止通过不断创建"补 SHA commit"追求自引用一致；Git 最终实际 HEAD 由 TRAE 简短回复和下一份报告 Starting State 记录；
3. `reports/LATEST.md` 三字段与目标报告一致，Report Published Through SHA = d99a5b；
4. 所有文字统一为"15 个检查组"（如需描述内部约束可写"15 个检查组，覆盖 18 类约束"）；
5. secret 检测正则要求等号后跟 ASCII 值，中文说明文字不误报；占位值白名单（`<redacted>` / `REDACTED` / `***` / `example` / `placeholder` 等）PASS；PEM 私钥标记无条件 FAIL；
6. 检查组 13 覆盖：三 SHA 存在、40 位十六进制、commit 有效性、祖先关系（Base→Implementation→Report Published Through）、Push Result 非空、LATEST 与报告一致、INDEX Implementation SHA 列存在且一致；
7. reports job 使用 `fetch-depth: 0` 完整历史，支持 SHA 祖先检查（其他 job 不变）；
8. 新增 `tools/tests/test_check_reports.py` 70 个自测用例。
