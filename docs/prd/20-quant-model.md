# 量化模型 PRD

状态：已确认
最后确认日期：2026-08-06
对应 Map：`../maps/20-quant-model.md`
需求所有权：趋势、结构、动量、筹码共识和板块模型

> 本文件拥有 DSA、SMC、动量、筹码共识及板块模型语义。跨域运行身份、readiness、publication 和产品闭环见 [`31-after-close-product-closure-v2.1.md`](./31-after-close-product-closure-v2.1.md)，不得由总纲重新定义本文件算法。

## 1. 目标

以统一因子和事件描述个股及板块当前状态，为盘后选股、市场理解、盘中监控和复盘提供基础。

## 2. 个股金字塔

### QM-01 维度顺序

个股状态按以下优先顺序组织：

```text
趋势 > 结构 > 动量 > 筹码共识
```

### QM-02 必选和可选

趋势、结构和动量为必选维度。筹码共识为可选维度，不要求每只股票都必须用筹码信息描述。

### QM-03 文字化输出

每只股票的因子结果应能够组合成中文状态描述，而不是只输出孤立数值。

## 3. 趋势

### QM-10 趋势职责

趋势用于描述长周期、相对难以改变的价格与成交量方向。

### QM-11 趋势算法

当前趋势由 DSA VWAP 体系承担，以日线为主。

### QM-12 趋势段与成交量

每段趋势至少记录：

- 方向；
- 起止位置；
- 持续长度；
- 价格变化；
- 平均成交量；
- 与前段的变化关系。

### QM-13 趋势与 SMC 边界

DSA 趋势段描述长周期方向；SMC 结构不得重复维护另一套等价趋势段。

## 4. 结构

### QM-20 结构职责

结构用于描述中周期价格高低点、突破和供需区域关系。

### QM-21 结构事件

至少包括：

- BOS；
- CHoCH；
- 进入 OB；
- 连续高点；
- 连续低点。

### QM-22 结构成交量

结构因子和事件应保留必要成交量信息，但不得与趋势维度重复定义长期方向。

### QM-23 Pine 对齐

SMC 实现需要与选定 Pine 参考语义对齐；不展示 FVG，不使用内部英文标签直接面向用户。

### QM-24 SMC 展示语义一致性

前端必须用同一格式化合同展示 SMC：BOS/CHoCH 按 `structureLevel(swing/internal) × direction(up/down)` 覆盖八种组合，OB 按级别与方向覆盖四种组合，未知输入显式显示“未知结构”，不得把未知值默认为多头或空头。`structureLevel=null` 只用于 EQH/EQL 等无级别事实，不得虚构主要或短线级别；事件 `direction` 与数值 `bias` 同时存在但冲突时必须保留可诊断的不一致状态。图表的文字、A 股红涨绿跌颜色、方向箭头和线型必须来自该语义合同；未失效的 Swing OB 与 Internal OB 均须渲染。

## 5. 动量

### QM-30 动量职责

动量描述较短周期的收缩、扩张、扩散及变化速度。

### QM-31 Bollinger 体系

当前动量以 Bollinger squeeze、扩张和扩散相关特征为主。

### QM-32 动量成交量

动量维度包含与价格扩张相匹配的成交量信息。

### QM-33 绝对与相对变化

动量同时记录：

- 当前绝对水平；
- 相对前期的变化；
- 事件新鲜度。

## 6. 筹码共识

### QM-40 可选定位

筹码共识主要服务于盘中监控和短周期解释，不作为盘后个股状态的强制维度。

### QM-41 Node Cluster

Node Cluster 本身已包含成交量信息，不再额外叠加独立成交量过滤。

### QM-42 禁止 VAH/VAL 范围替代

Node Cluster 不使用 VAH/VAL 区间过滤替代其自身逻辑。

### QM-43 事件

至少支持筹码峰上穿、下穿及新鲜度记录。

### QM-44 独立计算与动态增强

趋势、结构和动量构成可独立发布的 canonical stock core；筹码共识使用当日 ready 的 `15m` 数据异步计算，并作为动态增强合入读模型。chip 尚未完成、合法跳过或不可用时，不得阻塞或改写已经发布的 core，也不得用旧 chip 伪装当日结果。

## 7. 板块和指数层

### QM-50 第二金字塔

板块和指数层基于个股因子和事件聚合，依次检查：

1. 趋势是否受损；
2. 结构事件分布；
3. 动量绝对水平；
4. 动量相对变化；
5. 板块内部个股分布。

### QM-51 不直接预测

板块聚合用于描述市场状态和分布，不直接输出确定性涨跌结论。

## 8. 输出和版本

### QM-60 连续因子与事件分离

计算结果区分：

- 连续因子和特征；
- 离散事件；
- 事件发生时间；
- 事件新鲜度。

### QM-61 参数固定

正式盘后计算使用已确认固定参数。页面筛选不能重新组合策略或触发重新计算。

DSA 选股条件必须投影自同一 core run 中已经计算的 canonical DSA 结果；不得在选股、列表或 Review 路径另算一套 DSA，也不得让未执行的配置看起来已生效。

### QM-62 可追踪

正式结果应能追踪必要的输入日期、计算 run、参数或算法版本。一次计算 run 必须注入唯一 `calculated_at`，同 run 内所有个股快照和扁平读模型不得各自取时钟。

### QM-63 正式事件与可用性合同

`PyramidEvent` 顶层正式字段必须包含 `structureLevel`、`direction` 与 `bias`；结构层级与方向冲突必须输出诊断，不得静默覆盖。旧快照中 `extra.structure_level` 等历史字段只能通过兼容 adapter 读取。动量必须显式输出 availability 状态和不可用原因，不得以空值冒充中性。

筹码状态统一为七态：`strong_support`、`weak_support`、`neutral`、`weak_pressure`、`strong_pressure`、`unavailable`、`not_applicable`，并携带稳定的 label、tone、order 元数据。正式快照是第一金字塔读模型的唯一 canonical 来源，API、筛选与 Review 不得绕过快照重新计算或拼接另一份语义。

## 9. 验收标准

- 趋势、结构、动量不重复承担同一语义。
- 同一输入和固定参数得到稳定结果。
- 单股、股票池和全市场调用复用同一核心计算。
- QM 条款在 Map 中存在唯一权威实现入口和验证入口。
