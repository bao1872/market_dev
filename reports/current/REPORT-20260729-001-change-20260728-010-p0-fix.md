## 6. Behavior Before and After

### Before

- `computeCombinedReady` 内联于 `CaptureStockPage.tsx`，不可独立单元测试。
- `swing_bias` 类型判断错误：`Array.isArray(swingBias)`，但实际后端返回 `swing_bias: number`（1/-1/0）。
- 后果：`smcContractReady` 永远为 false → `combined Ready` 永远为 false → `data-render-ready` 永远不为 "true" → Capture Worker 30s 超时返回 502 → 飞书截图链路完全不可用。
- `sendStockDetailFeishu(instrumentId, payload?)` 携带无意义 `payload` 参数；`payload ? {} : {}` 无论 payload 是否存在均发送 `{}`。
- `CaptureJob.indicator_view` 注释只列历史值 `node_cluster|bollinger|smc`，未说明新业务固定写入 `structure_node`。

### After

- `computeCombinedReady` 提取为独立纯函数模块 `frontend/src/features/stock-research/captureReady.ts`，可独立单元测试。
- `swing_bias` 类型判断修正为 `typeof swingBias === 'number' && Number.isFinite(swingBias)`。
- 后果：`smcContractReady` 在 SMC DTO 完整时正确返回 true → `combined Ready` 正确反映数据就绪状态 → `data-render-ready` 在 node + smc 数据就绪后转为 "true" → Capture Worker 正常截图。
- `sendStockDetailFeishu(instrumentId)` 仅接受 `instrumentId` 参数，固定 POST `{}`。
- `CaptureJob.indicator_view` 注释：`指标视图 node_cluster|bollinger|smc(历史)|structure_node(新业务)`，schema 无变化。
- 新增 13 个单元测试用例，含 P0 根因回归保护（`swing_bias` 数组类型应返回 false）。
