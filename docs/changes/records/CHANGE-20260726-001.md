# CHANGE-20260726-001：项目治理 Phase 1 — 建立根 rules/ 并行规则体系

## 变更编号

CHANGE-20260726-001

## 任务名称

项目治理 Phase 1 — 建立根 rules/ 并行规则体系

## 需求出处

用户指令：执行项目治理第一阶段，建立根目录 `rules/`，把现有 `AGENTS.md` 中长期有效的强制规则按主题拆分。

## 修改前行为

1. 仓库无根 `rules/` 目录；
2. 所有长期强制规则集中在根 `AGENTS.md`（v3，含 §一-§十一与 §七 23 条硬规则，共 46 条章节/硬规则级条款）；
3. `sync/panji_agents_rules_maps_autodeploy_v2/` 草案提出 `rules/` + `maps/` 顶级目录重构，但属于设计草案，非正式真源；
4. Phase 0 审计报告（`sync/outbox/project-governance-audit.md`）建议先建立 `docs/governance/rules/` 过渡层；
5. 用户在 Phase 1 指令中明确修正：正式目标就是仓库根目录 `rules/`，不需要 `docs/governance` 过渡层。

## 修改后行为

1. 新建根目录 `rules/`，与 `AGENTS.md` 与 `docs/` 并行存在；
2. 从 `AGENTS.md` 提取 46 条章节/硬规则级条款，按主题拆分到 11 份规则文件 + 1 份 README + 1 份 AGENTS-MIGRATION-MAP；
3. `rules/` 与 `AGENTS.md` 并行验证：`AGENTS.md` 仍是最高正式权威，`rules/` 尚未替代 AGENTS；
4. `rules/README.md` 明确写：Phase 1 并行验证状态、AGENTS 仍具有最高正式权威、rules 尚未替代 AGENTS、docs/current 仍是当前事实源、sync 不是正式真源；
5. `rules/AGENTS-MIGRATION-MAP.md` 覆盖 `AGENTS.md` 全部章节（§一-§十一）与全部 23 条硬规则（§七.1-23）与全部 12 条禁止行为（§六），每条标记 KEEP_IN_AGENTS / MOVE_TO_RULES / MOVE_TO_MAPS / MOVE_TO_CHANGE / DEPRECATED_CANDIDATE；
6. PLANNED 内容（TRAE Work/CN 角色边界、三目录职责、自动部署）明确标记 PLANNED，不描述为已生效；
7. 不采用 `sync/` 草案中与 `AGENTS.md` 冲突的内容（事实源优先级第 3 位、Capability V2、自动部署已启用等）。

## 为什么建立根 rules/

- `AGENTS.md` 单文件 46 条规则按主题检索困难；
- 按主题拆分便于未来迁移到 `rules/` + `maps/` 顶级目录体系；
- 与 `docs/` 并行不冲突，`check_docs_consistency.py` 与 `check_architecture.py` 不扫描根 `rules/`，不影响 CI；
- 为 Phase 2（精简 AGENTS.md）与 Phase 3（建立根 maps/）做准备。

## 为什么不采用 docs/governance/rules/

- 用户在 Phase 1 指令中明确修正：正式目标就是仓库根目录 `rules/`；
- `docs/governance/rules/` 是 Phase 0 审计报告的建议，但用户判定不需要过渡层；
- 根 `rules/` 与 `docs/` 并行更清晰，避免在 `docs/` 下增加新子目录破坏 `check_docs_consistency.py` 规则 11 的 docs 顶级目录白名单；
- 根 `rules/` 与未来根 `maps/` 形成对称结构。

## 本阶段不改变 AGENTS 权威

- `AGENTS.md` 不修改、不精简、不重写；
- `rules/` 内容全部从 `AGENTS.md` 提取，与 `AGENTS.md` 一致；
- 当 `rules/` 与 `AGENTS.md` 出现冲突时，以 `AGENTS.md` 为准；
- `docs/current/` 仍是当前事实源；
- `docs/maps/` 仍是代码地图源；
- `sync/` 不是正式真源。

## 影响模块

- 文档治理：新增根 `rules/` 目录；
- 不影响：backend、frontend、worker、API、DB、migration、Compose、部署脚本、GitHub Actions、业务代码、测试。
