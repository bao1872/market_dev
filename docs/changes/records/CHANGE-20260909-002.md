## 1. 摘要

旧「使用说明」Help Center 曾与产品官网共用同一物理槽位 `dist/portal/index.html`，导致「谁最后部署谁赢」：
全量前端 build（vite 拷贝 `public/**`）把旧帮助中心首页落进 `dist/portal/index.html`，覆盖掉 Marketing 轻部署
写入的产品官网。本轮彻底删除 `frontend/public/portal/**`，产品官网改用唯一部署槽位 `dist/site/index.html`，
nginx 根路径指向 `/site/index.html`，`/portal/` 一律 301 到根；并从全量部署 `rsync --delete` 中排除
`site/` 与 `marketing-assets/`，确保任意顺序部署后 `/` 都是产品官网。

## 2. 背景与问题

- 变化前，`frontend/public/portal/index.html`（title =「使用说明首页｜盘迹使用说明」）仍在仓库中。
- 全量前端 build 把它复制进 `dist/portal/index.html`，而 Marketing 轻部署也把产品官网 install 到同一文件，
  nginx `location = /` 精确读 `/portal/index.html` ⇒ 全量 build 一执行，旧帮助中心就「复活」覆盖产品官网。
- 此前仅把 portal 从根入口退役，未物理删除源码，也未拆除共享部署槽位，属于 SSOT 结构债。

## 3. 变化前

- `frontend/public/portal/**`：index.html + pages/* + assets/* + content/* + SOURCE.md（完整旧帮助中心）。
- nginx `location = /` → `try_files /portal/index.html =404;`，残留 `/portal/index.html`、`/portal/pages/*`、
  `/portal/` 配置。
- `panji-marketing-site-deploy` 把产品官网 install 到 `${LIVE_ROOT}/frontend/dist/portal/index.html`。
- 全量部署 `panji-deploy.sh` 以 `rsync -a --delete` 同步 `frontend/dist/`，会清除营销写入的 `dist/site`。
- App 消费方：`LandingPage` 有「使用说明」链接（`/portal/index.html`）；`MobileIndicatorStage` 有指向
  已删除 `pages/data.html` 的指标原理 QR 页脚。

## 4. 变化内容

- 删除 `frontend/public/portal/**`（`index.html`、`pages/*`、`assets/*`、`content/*`、`SOURCE.md`）。
  全量 build 因此不再产出 `dist/portal/*`。
- nginx.conf：`location = /` → `try_files /site/index.html =404;`；新增 `location = /site/index.html`
  禁缓存；删除 `/portal/index.html`、`/portal/pages/*`、`/portal/` 旧配置；新增退役 tombstone
  `location ^~ /portal/ { return 301 /; }`。
- `panji-marketing-site-deploy`：`CURRENT_ROOT_HTML` 改到 `dist/site/index.html`；新增防回归 SSOT 校验，
  根 HTML 不得含「使用说明首页/盘迹使用说明中心/快速开始/帮助中心//portal/」。
- `panji-deploy.sh` `sync_frontend_runtime`：`rsync --delete` 显式 `--exclude='site/'`、
  `--exclude='marketing-assets/'`，保护营销轻部署产物不被全量部署清掉。
- App 消费方：移除 `LandingPage`「使用说明」链接；移除 `MobileIndicatorStage` 指标原理 QR 页脚
  （保留免责声明）。
- 契约测试：`portal-static.test.ts` → 重命名为 `public-site-slot.contract.test.ts`（断言 portal 已删、
  nginx 根槽位 `/site`、全量部署 exclode site/），删除引用已删 portal 文件的 `portal-autoplay.test.ts`
  与 `portal-svg-render.test.ts`；更新 `capture-stock-page`、`landingPageRoot`、`marketingCopy`、
  `marketingCanonicalUrl` 契约断言。

## 5. 变化后

- `/` → 产品官网（`dist/site/index.html`，只由 Marketing 轻部署写入）；旧 `/portal/*` 一律 301 到 `/`。
- 全量 build 不产出 `dist/portal`；全量部署不会删除 `dist/site`；任意顺序部署后 `/` 都是产品官网。
- `LandingPage` DEV 跳 `/marketing-site/`（产品官网），不再跳旧 portal。
