## 7. MARKET / WATCHLIST FINAL CONTRACT
`WorkspaceResult = BaseUniverse ∩ ActiveWorkspaceFilters`；Market BaseUniverse = canonical market universe；Watchlist BaseUniverse = 当前用户 canonical active 自选成员；任何 filter 不引入非自选；filter 可叠加（非 multi-select/AND-OR/UQB）。

## 8. PERMISSION FINAL CONTRACT
Market access 控制 Global Search 主点击进 Market；Watchlist Management（self_selection capability）控制 ☆/★ 与 limit；两 action 独立权限判断。前端隐藏 ≠ 安全；完整链 Capability→/me/access→nav→default route→guard→action guard→backend authz，服务端 enforce。无 Market access 时按 PRD 60 既有 insufficient-permission 行为，不 fallback Watchlist。合同 owner = PRD 60。

## 9. INVITATION FINAL CONTRACT
邀请码 = provisioning，非运行时权限本身；InviteCode→registration/activation→UserCapability/Entitlement→runtime access；可配 capability（含 self_selection）、watchlist_limit；revoke/expiry 后由 resolve_effective_access 收敛。runtime 不依赖 invite code 本身做权限判断。owner = PRD 60 §3。

**邀请码为一次性 provisioning token（Round 1.2 冻结 R22）**：一个邀请码 `unused → 首次成功兑换 → used`，或 `unused → admin revoke → revoked`；`used` / `revoked` 均不可再次兑换；管理员无 reusable 配置。InviteRedemption 只保存成功兑换审计历史，不改变 InviteCode single-use 语义。runtime 权限仍通过 InviteCode provisioning → capability / entitlement → effective access 决定，邀请码本身不作为 runtime permission owner。正式代码已确认 single-use（`register_with_invite_code` 在 `status=='used'`/`'revoked'` 时均 `raise ValueError`，且 `with_for_update()` 行锁防并发二次兑换），SHOULD=ACTUAL=single-use，GAP=NONE，CLASS=ALIGNED，不进入 Round 2 implementation。PRD 60 PA-21 已冻结为严格 single-use 合同，不提供"允许重复使用"配置项（不改其他权限/邀请码合同）。
